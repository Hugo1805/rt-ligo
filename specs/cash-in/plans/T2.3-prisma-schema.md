## Objetivo
Modelo de datos de design §10 como schema Prisma, primera migración aplicada en dev y en test, y seed de wallets.

## Contexto
Las restricciones únicas del schema son la garantía de idempotencia del sistema. Son la parte más importante de esta tarea.

## Pasos
1. Copiar los enums y modelos de design §10 tal cual, incluyendo cada `@unique`, `@@unique` e `@@index`.
2. Configurar el generador y el datasource según la versión estable de Prisma instalada.
3. `bunx prisma migrate dev --name init`.
4. Seed con `upsert` por `userId`:

| userId | currency | balance |
|---|---|---|
| `usr_abc123` | PEN | 250.00 |
| `usr_test_1` | PEN | 0.00 |
| `usr_test_2` | PEN | 0.00 |

   Con `usr_abc123` en 250.00, una recarga de 100.00 da `new_balance` 350.00, igual que el ejemplo del PDF.

5. `src/infra/prisma.ts` exporta `createPrismaClient(databaseUrl: string)`. Cada pod y cada test de concurrencia crea su propio cliente.
6. Aplicar la migración a la base de test con las variables de `.env.test`.

## Restricciones
- Montos siempre `Decimal @db.Decimal(18, 2)`. Nunca `Float`.
- `idempotencyKey` como `@db.Uuid`.
- El `id` de `CashInOperation` lo genera la app como `op_` seguido de `Bun.randomUUIDv7()` sin guiones. No usar `@default` en ese campo.
- Seed solo con cliente Prisma.

## Trampas conocidas
- El agente tiende a omitir `@@unique([userId, idempotencyKey])` o a ponerlo solo sobre `idempotencyKey`. La key tiene alcance por usuario.
- El agente tiende a olvidar `@unique` en `LedgerEntry.operationId`. Sin eso puede haber doble abono.
- El agente tiende a usar `Float` para montos.
- El agente tiende a crear un `export const prisma = new PrismaClient()` global. Los tests de concurrencia necesitan varios clientes.
- Prisma 7 cambia la configuración, y el agente tiende a usar la de Prisma 5 o 6:
  - El generador es `provider = "prisma-client"` con `output = "../src/generated/prisma"`, que ya está en `.gitignore`. Se importa desde esa ruta, no desde `@prisma/client`.
  - La URL de la base va en `prisma.config.ts`, no en el bloque `datasource` del schema.
  - El cliente se construye con el adapter: `new PrismaClient({ adapter: new PrismaPg({ connectionString }) })`, usando `@prisma/adapter-pg`, que ya está instalado.
  - `migrate dev` ya no corre `generate` ni el seed. Correr `bun run db:generate` explícitamente, y declarar el seed en `prisma.config.ts` si se usa `prisma db seed`.
  - `prisma.config.ts` no carga `.env` solo. Correr el CLI con `bunx --bun prisma ...` para que Bun cargue el `.env`, sin agregar `dotenv`.
