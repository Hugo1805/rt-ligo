## Objetivo
`cash-in.repository.ts` con alta de operación que detecta duplicados por `P2002`, búsqueda por `(userId, idempotencyKey)` y por id, y transiciones compare-and-set con `updateMany`.

## Contexto
Es la capa 2 de design §2 y la garantía real de idempotencia. Dos pods que crean la misma operación a la vez: uno gana el `create`, el otro recibe `P2002` y devuelve la existente.

El `id` lo genera la app: `op_` + `Bun.randomUUIDv7()` sin guiones. El schema no tiene `@default` en ese campo (T2.3).

El webhook (T5.1) necesitará hacer el CAS a `FAILED` dentro de su propia transacción. Por eso el repositorio se construye sobre un cliente que puede ser el `PrismaClient` o un cliente de transacción.

`allowedSources(to)` viene de `src/shared/operation-state-machine.ts` (T3.1).

## Pasos
1. `newOperationId()`: `"op_" + Bun.randomUUIDv7().replaceAll("-", "")`.
2. `createCashInRepository(db: DbClient)` devuelve:

| Método | Comportamiento |
|---|---|
| `create(input)` | `db.cashInOperation.create` con `status: "PENDING"`. Devuelve `{ kind: "created", operation }`. Si captura `P2002`, hace `findByKey` y devuelve `{ kind: "duplicate", operation }`. |
| `findByKey(userId, idempotencyKey)` | `findUnique` por `userId_idempotencyKey`. Incluye `ledgerEntry.balanceAfter`. |
| `findById(id)` | `findUnique` por `id`. Incluye `ledgerEntry.balanceAfter`. |
| `transition(id, to, data?)` | `updateMany({ where: { id, status: { in: allowedSources(to) } }, data: { status: to, ...data } })`. Devuelve `true` si `count === 1`, `false` si `count === 0`. |

3. `input` de `create`: `userId`, `idempotencyKey`, `requestHash`, `amount: Prisma.Decimal`, `currency`, `paymentMethod`.
4. `data` de `transition` admite solo `providerChargeId`, `failureCode` y `lastError`.
5. `to` en `transition` se tipa como `"PROCESSING" | "UNKNOWN" | "FAILED"`. A `COMPLETED` solo se llega por `applyCredit` (T4.5), que acredita en la misma transacción.
6. Detectar el duplicado con `error instanceof Prisma.PrismaClientKnownRequestError && error.code === "P2002"`. Cualquier otro error se relanza tal cual.
7. Factories de test con datos únicos: `uniqueUserId()` devuelve `usr_t_<uuid>`, `createWallet` crea una wallet PEN con saldo 0 por defecto, `createOperation` crea una operación con estado y monto configurables e `idempotencyKey` aleatoria.
8. Tests de integración, cada uno con su propio `userId` único:
   - `create` nuevo devuelve `created` con id `op_` de 35 caracteres y estado `PENDING`.
   - Segundo `create` con la misma `(userId, key)` devuelve `duplicate` con el mismo id.
   - Misma `key` con otro `userId` crea otra operación (alcance por usuario, R2.3).
   - `Promise.all` de 10 `create` con la misma `(userId, key)` desde 3 clientes Prisma distintos: una sola fila, un `created` y nueve `duplicate`, todos con el mismo id.
   - `transition` `PENDING→PROCESSING` devuelve `true`. Repetirla devuelve `false`.
   - `transition` desde un estado terminal devuelve `false` y no cambia la fila.
   - Dos `transition` concurrentes `PROCESSING→FAILED` y `PROCESSING→UNKNOWN`: solo una devuelve `true`.
   - `transition` usado con un cliente de transacción se revierte si la transacción falla.

## Restricciones
- Solo cliente Prisma. Prohibido `$queryRaw`, `$executeRaw` y SQL a mano.
- Montos como `Prisma.Decimal`, nunca `number`.
- El repositorio no loguea transiciones. Lo hace quien conoce el `actor` (T4.6, T5.1, T6.1).
- No exportar una instancia del repositorio a nivel de módulo.

## Trampas conocidas
- El agente tiende a hacer un `findUnique` antes del `create` para "ver si existe". Es una carrera entre pods. El duplicado se detecta capturando `P2002`.
- El agente tiende a usar `update` en lugar de `updateMany` para las transiciones. `update` no admite filtrar por estado de origen sin lanzar `P2025`, y el CAS se pierde.
- El agente tiende a ignorar el `count` del `updateMany`. Sin chequearlo no se sabe si otro actor ganó.
- El agente tiende a escribir la lista de estados de origen a mano en el repositorio. Se usa `allowedSources(to)` de T3.1.
- El agente tiende a usar `Bun.randomUUIDv7()` con guiones o `crypto.randomUUID()` (v4). El id es v7 sin guiones, así es ordenable por tiempo.
- En Prisma 7 con driver adapter, `error.meta.target` puede no traer el nombre de la restricción. No decidir el duplicado por `meta.target`; basta con `code === "P2002"`.
- El agente tiende a importar `PrismaClient` desde `@prisma/client`. Se importa desde `src/generated/prisma/client` o desde `src/infra/prisma.ts`.
- El agente tiende a reutilizar el seed (`usr_test_1`) en los tests. Cada test crea su propia wallet con `uniqueUserId()`.

## Criterios de aceptación
- [ ] `create` concurrente con la misma `(userId, key)` deja una sola fila y todos los llamadores reciben el mismo id.
- [ ] La misma key con distinto `userId` crea operaciones distintas.
- [ ] `transition` usa `updateMany` con `allowedSources(to)` y devuelve `false` si `count === 0`.
- [ ] `transition` no acepta `COMPLETED` en sus tipos.
- [ ] El id cumple `^op_[0-9a-f]{32}$`.
- [ ] Cada test usa un `userId` único y cierra sus clientes Prisma en `afterAll`.
- [ ] `grep -r "queryRaw\|executeRaw" src` no encuentra nada.
