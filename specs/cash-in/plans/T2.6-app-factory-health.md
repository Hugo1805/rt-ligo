## Objetivo
`createApp(deps)` arma la app Hono con dependencias inyectadas. `server.ts` la arranca con apagado ordenado. `GET /health` informa el estado de PostgreSQL y Redis.

## Contexto
La inyección de dependencias permite levantar varias instancias de la app en un mismo test, cada una con su cliente Prisma y Redis. Así se simulan pods en los tests de integración.

## Pasos
1. `AppDeps` contiene `config`, `logger`, `prisma` y `redis`. Las fases siguientes agregan `paymentProvider` y `lock`.
2. `createApp(deps)` registra el middleware de correlation y monta las rutas de cada feature. No crea clientes.
3. `createRedisClient(url)` con `connectTimeout` y `commandTimeout` cortos, y `maxRetriesPerRequest` bajo. Si Redis cae, los comandos deben fallar rápido para que la app use el fallback a PostgreSQL.
4. `GET /health`:
   - PostgreSQL: una consulta mínima con el cliente Prisma, por ejemplo `prisma.wallet.findFirst({ select: { id: true } })`.
   - Redis: `PING`.
   - `200 { "status": "ok", "postgres": "up", "redis": "up" }` si ambos responden.
   - `200` con `"status": "degraded"` y `"redis": "down"` si solo falla Redis.
   - `503` con `"postgres": "down"` si falla PostgreSQL.
5. `server.ts` exporta el servidor con `Bun.serve` y maneja `SIGTERM` y `SIGINT`: deja de aceptar requests, desconecta Prisma y Redis, y termina.

## Restricciones
- Prohibido `$queryRaw` para el health check. Se usa una consulta del cliente Prisma.
- `createApp` no lee `process.env`.
- Hasta T3.2, el `onError` puede devolver un 500 mínimo. T3.2 lo reemplaza por el error handler definitivo.

## Trampas conocidas
- El agente casi siempre usa `prisma.$queryRaw\`SELECT 1\`` en un health check. Está prohibido en este repo.
- El agente tiende a crear los clientes dentro de `createApp`, lo que impide inyectar varios en los tests.
- El agente tiende a dejar ioredis con reintentos infinitos por defecto, y con Redis caído el request se cuelga en vez de fallar rápido.

## Criterios de aceptación
- [ ] Con dependencias falsas sanas, `GET /health` responde `200 ok`.
- [ ] Con Redis falso caído, responde `200 degraded`.
- [ ] Con Prisma falso caído, responde `503`.
- [ ] Con Postgres y Redis reales, el test de integración responde `200 ok`.
- [ ] `bun run dev` levanta y `curl localhost:3000/health` responde con `X-Request-Id`.
- [ ] `grep -r "queryRaw\|executeRaw" src` no encuentra nada.
